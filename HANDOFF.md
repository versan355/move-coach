# MOVE — передача проекта

Первая рабочая версия по исходному перечню требований. Прототипы, материалы преподавателя и доступы к Telegram не предоставлены, поэтому направление выбрано как демонстрационный пример: движение и танцы. Это авторская реализация на Vinext/React, без готового дизайн-макета.

## Что готово

- Два оформления: `/?style=base` — светлый классический; `/?style=bold` — контрастный авторский. Переключатель в верхней панели; предпочтение сохраняется на устройстве.
- 15 разделов лендинга: первый экран, философия, аудитория, преподаватель, направления, подход, программа, пробная практика, прогресс, форматы, расписание, тарифы, Telegram-кабинет, FAQ, заявка.
- Адаптивная вёрстка, мобильное меню, выбор недели, слота и формата. Пробная практика состоит из трёх текстовых шагов; это не видеоплеер.
- `/mini` — интерфейс Mini App с Telegram SDK, разворачиванием окна и предупреждением о закрытии при отправке.
- ДЗ: выбор задания, комментарий, drag-and-drop, превью фото/видео, удаление из очереди, последовательная загрузка с реальным XHR-прогрессом. До пяти файлов по 20 МБ: JPEG, PNG, WebP, MP4, WebM, MOV.
- D1 хранит заявки, задания и метаданные; R2 — файлы. История показывает последние 50 работ текущего пользователя. В браузере используется идентификатор Sites; в Telegram — проверенная сервером подпись initData.
- Бот: отправляет преподавателю файлы и уведомление с кнопками «Принять» / «На доработку». Webhook проверяет секрет, ID преподавателя и чат; повторные нажатия не меняют уже проверенную работу. Статус сохраняется в базе. Ученику отправляется уведомление, если бот может ему написать.
- Сбой Telegram не удаляет работу. В истории есть повторная отправка неудавшегося уведомления. При частичном сбое Telegram возможна повторная доставка части файлов; статус проверки в базе остаётся однозначным.

## Статус запуска

Сайт в Sites публикуется приватно, для владельца. Это адрес для просмотра проекта, а не открытый набор учеников. У приватного сайта есть вход через ChatGPT: Telegram не сможет вызывать его webhook напрямую. Для боевого запуска нужен публично доступный HTTPS-деплой либо отдельно доступный сервер API; изменение аудитории текущего сайта не выполнялось.

Токен бота, ID преподавателя, webhook и меню бота **не подключены**. Уведомления настоящему преподавателю не отправлялись. Автоматический ответ на заявки не реализован: заявка сохраняется в D1, данные доступны владельцу через инструменты базы Sites. Оплата и админ-панель не входят в эту реализацию.

## Как подключить Telegram

1. Создать своего бота в BotFather. Преподавателю открыть бота и нажать Start.
2. Разместить проект с доступным Telegram HTTPS-адресом. D1 и R2 обязательны. Применить SQL из `drizzle/` по порядку; в Sites это делает публикация.
3. В серверном окружении безопасно задать `TELEGRAM_BOT_TOKEN`, `TELEGRAM_TEACHER_CHAT_ID`, `TELEGRAM_TEACHER_USER_ID`, `TELEGRAM_WEBHOOK_SECRET`. Имена показаны в `.env.example`; значений в исходниках нет. Секрет webhook должен соответствовать `[A-Za-z0-9_-]{1,256}`.
4. В процессе запуска скрипта задать те же `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` и `TELEGRAM_MINI_APP_URL=https://ваш-домен/mini`, затем выполнить `node scripts/connect-telegram.mjs`. Скрипт проверяет доступность webhook, вызывает setWebhook и настраивает кнопку меню. Не передавать токен аргументом командной строки.
5. В BotFather настроить Main Mini App при необходимости прямых `startapp`-ссылок. Для кнопки меню используется URL `/mini`.
6. Проверить реальным учеником: открыть Mini App, отправить фото и видео, получить уведомление преподавателю, нажать обе кнопки на разных работах, сверить статусы и повторные нажатия. Этот внешний тест требует настоящего бота и пока не выполнен.

Подпись initData принимается один час с auth_date. После истечения сессии приложение нужно открыть заново. Исходные данные подписи передаются заголовком, не в URL. Файлы скачиваются после проверки владельца. Не использовать этот проект без настройки доступа и политики обработки данных для реальных персональных материалов.

Документация, по которой реализованы сценарии: [Mini Apps и валидация initData](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app), [setWebhook](https://core.telegram.org/bots/api#setwebhook), [callback queries](https://core.telegram.org/bots/api#answercallbackquery).

## Что заменить до реального запуска

Нужны прототипы 15 экранов, имя и направление тренера, реальные фотографии, палитра и тон, программа, подтверждённые цены и расписание. Демонстрационные тексты и стоковые фотографии не являются утверждениями об опыте конкретного преподавателя. Отзывов и вымышленных результатов нет.

Добавить реквизиты оператора, окончательную политику и сроки хранения материалов. Сейчас согласие сообщает о сохранении в проекте; автоматическое удаление старых и незавершённых загрузок не настроено. Есть ограничения отправок: 30 файлов, 10 ДЗ и 5 заявок на пользователя за час. Это базовые ограничения; для публичного трафика нужны эксплуатационные лимиты и мониторинг.

## Разработка и проверка

Node.js 24; `npm ci`; `npm run dev -- --port 4175`. На этом компьютере Windows резервирует диапазон с портом 5173. Локальный Cloudflare runtime не завершил запуск; при проверке интерфейса использовался отдельный Vite preview. Успешность реального Telegram не имитируется.

Команды проверки:

```text
npx tsc --noEmit
node --test scripts/telegram.test.mjs scripts/api.test.mjs
npm run build
```

Тесты API исполняют реальную логику маршрута с SQLite в памяти, адаптером D1, тестовым R2 и подменённым ответом Telegram. Они не выполняют сетевые вызовы к настоящему боту. Браузерная проверка охватывает оба оформления, мобильную ширину, отсутствие горизонтальной прокрутки, программу, мини-практику и кабинет.

Главные файлы: `app/studio.tsx` — лендинг и тексты; `app/globals.css` — оба дизайна и адаптив; `app/homework.tsx` — кабинет; `app/api/[...path]/route.ts` — API и webhook; `lib/telegram.ts` — проверка подписи и Bot API; `db/schema.ts` и `drizzle/` — схема и миграции.
